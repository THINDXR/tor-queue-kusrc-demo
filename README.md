# ต่อคิว — แอปต่อคิวและสั่งอาหาร โรงอาหาร ม.เกษตร ศรีราชา

แอปทำงานได้จริงทั้งฝั่งลูกค้าและฝั่งร้าน ผูก state เดียวกัน กดฝั่งร้านแล้วบัตรคิวฝั่งลูกค้าเปลี่ยนทันที

**Vite + React 19 + TypeScript** — ไม่มี dependency นอกเหนือจาก React

## เริ่มงาน

```bash
npm install     # ครั้งแรกครั้งเดียว
npm run dev     # เปิด http://localhost:5173
```

`npm run dev` จะโชว์ URL ของเครือข่ายด้วย เอาไปเปิดจากมือถือในวง Wi-Fi เดียวกันได้เลย

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | เซิร์ฟเวอร์พัฒนา แก้โค้ดแล้วหน้าจอเปลี่ยนทันทีไม่ต้องรีเฟรช |
| `npm test` | รันเทสต์ทั้งหมด |
| `npm run test:watch` | รันเทสต์ค้างไว้ แก้โค้ดแล้วรันใหม่เอง |
| `npm run typecheck` | ตรวจ TypeScript อย่างเดียว |
| `npm run build` | ตรวจ type แล้ว build ลง `dist/` สำหรับ deploy |

## ปุ่มสลับบทบาท

มุมขวาบนมีปุ่ม **ลูกค้า / ร้านค้า** ใช้เดโมทั้งสองฝั่งจากหน้าจอเดียว

## แนวคิดหลักที่ฝังอยู่ในโค้ด

**จานที่เหมือนกันแทนกันได้** เมื่อ 5 คนสั่งกะเพราหมูเหมือนกัน ไม่มีใครสนว่าได้จานไหน แอปจึงไม่ติดตามว่าจานไหนของใคร แต่ติดตาม *ลำดับการส่งมอบ* แทน — ดู `groupsOf()` ใน [src/lib/queue.ts](src/lib/queue.ts)

ผลที่ตามมาสองข้อ:

1. **ออเดอร์เหมือนกันถูกจับกลุ่มให้แม่ค้า** หน้าจอร้านขึ้นว่า `กะเพราหมู ×3` เป็นการ์ดเดียวปุ่มเดียว ผัดรวดเดียวได้เลย เร็วกว่าเดิม — นี่คือเหตุผลที่แม่ค้าจะยอมใช้แอป
2. **ออเดอร์พิเศษไม่เคยถูกจับกลุ่ม** `ไม่เผ็ด` `ไม่ใส่ผัก` คือออเดอร์ที่แทนกันไม่ได้จริง จึงแยกการ์ดพื้นดำขอบเหลืองเสมอ

**ปัญหา "จานไหนของฉัน" แก้ด้วยจังหวะเวลา ไม่ใช่ป้าย** แจ้งเตือนให้ลูกค้าเดินมารอตั้งแต่เหลืออีก 2 คิว อาหารจึงส่งมือต่อมือจากกระทะ ไม่ต้องวางรอบนชั้นปนกับจานที่หน้าตาเหมือนกัน

**อัตลักษณ์บัตรคิว = สี + รูปทรง เสมอ** ไม่ใช้สีอย่างเดียว เพราะผู้ชายไทยราว 8% ตาบอดสี และโรงอาหารแสงจ้าจนสีเพี้ยน 8 แบบหมุนเวียนโดยเลขคิวติดกันไม่มีทางซ้ำกัน — ดู [src/lib/identity.ts](src/lib/identity.ts)

**ข้อจำกัด: ร้านไม่ต้องซื้ออะไรเพิ่ม** ไม่มีจอเรียกคิว ไม่มีเครื่องพิมพ์ ไม่มีป้ายเลข มือถือแม่ค้าเครื่องเดียวกับมือถือลูกค้าคือทั้งระบบ การประกาศเสียงเรียกคิวใช้ Web Speech API พูดภาษาไทยจากลำโพงมือถือ แทนจอเรียกคิว

## วงจรสถานะออเดอร์

```
รอชำระ ──(แม่ค้ากดรับเงิน)──┐
                            ├─→ เข้าคิว ─→ กำลังทำ ─→ รับได้ ─→ รับแล้ว
สแกนจ่าย ───────────────────┘                          │
                                                       └─(ไม่มารับ)→ ท้ายแถว
```

- คิวเงินสด **ไม่เข้าคิวทำอาหาร** จนกว่าแม่ค้าจะกดรับเงิน กันคนสั่งทิ้ง
- ไม่มาจ่ายภายใน 5 นาที ยกเลิกอัตโนมัติ
- ไม่มารับ ข้ามไปท้ายแถวได้ครั้งเดียว ครั้งที่สองยกเลิก
- อีก 2 คิวถึงตัว แจ้งเตือน "เดินมารอได้เลย"

ค่าคงที่ทั้งหมดอยู่หัวไฟล์ [src/lib/queue.ts](src/lib/queue.ts) (`COOK_WINDOW`, `CASH_TIMEOUT`, `PREPARE_AT`)

## โครงไฟล์

```
src/
  lib/          ตรรกะล้วน ไม่มี React — เทสต์ง่ายและย้ายไปฝั่ง server ได้เลย
    types.ts      ชนิดข้อมูลกลาง
    thai.ts       แปลงเลขเป็นคำอ่านไทย ใช้ประกาศเสียง
    identity.ts   ระบบสี+รูปทรงประจำบัตรคิว
    data.ts       ร้าน เมนู คิวตั้งต้น
    queue.ts      การจับกลุ่ม การเรียงคิว ค่าคงที่
    store.ts      สถานะทั้งแอป + คำสั่งทั้งหมด
  components/   ชิ้นส่วนที่ใช้ร่วมกันสองฝั่ง
  customer/     หน้าจอฝั่งลูกค้า
  vendor/       หน้าจอฝั่งร้าน + แผ่นส่งมอบ
  styles.css    design system ทั้งหมด
prototype/      เวอร์ชันแรก vanilla JS เปิดได้โดยไม่ต้องติดตั้งอะไร
```

**ทำไมแยก `lib/` ออกจาก component:** ตรรกะคิวทั้งหมดเป็นฟังก์ชันบริสุทธิ์ที่ไม่รู้จัก React เลย เทสต์ได้โดยไม่ต้องเรนเดอร์อะไร และวันที่ทำ backend จริง ย้ายทั้งโฟลเดอร์ไปรันฝั่ง server ได้ทันที

## การแจ้งเตือน

จุดประสงค์ของแอปคือให้ลูกค้าไปนั่งโต๊ะได้ ถ้ายังต้องจ้องหน้าจอรอก็เท่ากับไม่ได้แก้ปัญหาอะไร
การแจ้งเตือนจึงยิงผ่าน service worker ([public/sw.js](public/sw.js)) ไม่ใช่ `new Notification()`
ตรง ๆ เพราะบน Android Chrome การเรียกจากหน้าเว็บถูกบล็อก และ iOS ต้องเป็น PWA ที่ติดตั้งแล้ว

แจ้งเตือน 2 จังหวะ — "อีก 2 คิวถึงคุณ" และ "รับได้แล้ว" (ใบหลังค้างไว้จนกว่าจะแตะ)
แตะแล้วเด้งกลับเข้าบัตรคิวใบนั้นทันที ทั้งสองใบใช้ `tag` เดียวกันต่อหนึ่งออเดอร์ ใบใหม่จึงทับใบเก่า

**ทำงานได้ตอนนี้**

| สถานการณ์ | ได้รับแจ้งเตือนไหม |
|---|---|
| สลับไปแอปอื่น / ปิดหน้าจอ (เบราว์เซอร์ยังไม่ถูกปิด) | ได้ |
| สลับไปแท็บอื่นบนคอม | ได้ + ชื่อแท็บเปลี่ยนเป็น 🔔 |
| iPhone ที่กด "เพิ่มไปยังหน้าโฮม" แล้ว | ได้ |
| iPhone ที่เปิดผ่าน Safari เฉย ๆ | ไม่ได้ (ข้อจำกัดของ iOS เอง) |
| ปิดเบราว์เซอร์ทิ้งไปเลย | **ยังไม่ได้** ต้องทำ Web Push + backend ก่อน |

ช่องสุดท้ายคือช่องที่ต้องมี server เท่านั้นถึงจะทำได้ เพราะต้องมีคนคอยยิง push
เข้าหาเครื่องลูกค้าตอนที่แอปไม่ได้รันอยู่ ดูข้อ 2 ในก้าวต่อไป

## ข้อจำกัดตอนนี้

- ข้อมูลอยู่ใน localStorage ของเบราว์เซอร์ ยังไม่มี backend สองเครื่องจึงยังไม่เห็นคิวเดียวกัน
- แจ้งเตือนตอนปิดเบราว์เซอร์ไปแล้วยังไม่ได้ ต้องมี backend ก่อน (ดูตารางด้านบน)
- QR พร้อมเพย์ยังเป็นปุ่มจำลอง ยังไม่ได้ต่อ payment gateway จริง
- เสียงเตือนฝั่งแม่ค้าจะยังไม่ดังจนกว่าจะมีการแตะหน้าจอครั้งแรก เป็นกฎของเบราว์เซอร์เอง

## ก้าวต่อไป

1. **deploy ขึ้น Vercel** — `npx vercel` ได้ลิงก์จริงไปเสนอ
2. **ต่อ backend** — เปลี่ยน `save()`/`load()` ใน store.ts ให้ยิง API แล้วเติม WebSocket ให้สองเครื่องเห็นคิวเดียวกัน พร้อมกันนั้นเติม Web Push (VAPID) เพื่อให้แจ้งเตือนได้แม้ปิดเบราว์เซอร์ไปแล้ว
3. **ต่อ payment gateway** สำหรับสแกนจ่าย
